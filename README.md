# TLLB AI DM Setter

An autonomous Instagram DM setter for The Lean Lifestyle Blueprint. It replies to Instagram DMs that come
in through GoHighLevel, runs the conversation to your setter manual in your voice, books qualified leads
onto a call, and hands everything else to you.

```
Instagram DM → GoHighLevel workflow → webhook → setter (Claude + your manual) → reply sent through GHL
                                                        └→ hand-off: tag "setter-needs-human" and go quiet
```

## How it's "trained"

No model fine-tuning is needed. The bot reads its training material on every reply (cached, so it's cheap):

| File | What it is | Source |
|---|---|---|
| `knowledge/script.md` | The conversation framework: stages, questions, hand-off rules | Your DM Setter Training Manual |
| `knowledge/voice.md` | How you write: length, emojis, phrase bank, do's and don'ts | Your Setter Communication Style Guide |
| `knowledge/offer.md` | The only program facts the bot may state | **You fill this in** |
| `knowledge/playbook.md` | What your real conversations show works | Generated by `scripts/train.py` |
| `data/examples.jsonl` | Your best booked conversations, used as examples | Generated by `scripts/train.py` |

The original PDFs are in `knowledge/source/`. To change the bot's behaviour, edit the markdown files.

### Teaching it from your real DMs
1. Export DM conversations (GHL, Instagram data download, copy-paste, anything) into `data/raw/` as
   `.txt`, `.csv`, `.json` or `.pdf`. Mark outcomes where you can, e.g. `OUTCOME: booked`.
2. Run `python -m scripts.train`. It pulls out each conversation (anonymised), picks the best booked ones
   as examples, and writes `knowledge/playbook.md`.
3. Review the playbook, then run the evals.

`data/raw/` is gitignored, so client chats never go to GitHub.

## Setup

```bash
pip install -r requirements.txt
cp .env.example .env        # fill in your keys
python -m pytest            # offline tests
python -m setter.simulate   # chat with the bot as a lead, in your terminal
python -m evals.run         # simulated leads, graded against the manual → evals/report.md
```

## Going live on GoHighLevel

1. **API token:** in your GHL sub-account go to Settings → Private Integrations → create a token with the
   conversations, conversation-messages and contacts read/write scopes. Put it in `GHL_API_TOKEN` and set
   `GHL_LOCATION_ID`.
2. **Deploy** the server somewhere with a public HTTPS URL (Railway, Render, Fly.io, a VPS):
   `uvicorn setter.server:app --host 0.0.0.0 --port 8000`. Run a **single instance**: it batches a lead's
   rapid-fire messages in memory. Mount `data/` on persistent storage.
3. **Workflow:** in GHL, create a workflow with the trigger **Customer Replied**, filtered to reply channel
   **Instagram**, and the action **Webhook** → `POST https://<your-server>/webhook/ghl?secret=<WEBHOOK_SECRET>`.
4. **Soft launch** with `DRY_RUN=true`. The bot logs what it *would* send without sending it. Read the logs
   for a few days, then set `DRY_RUN=false`.

## Safety controls

| Control | How |
|---|---|
| Kill switch | `BOT_ENABLED=false` and restart |
| Stop the bot for one lead | Add the tag `setter-bot-off` in GHL, or `POST /leads/{contactId}/pause` |
| You jump in | Just reply in GHL. The bot stays quiet on that thread for `HUMAN_TAKEOVER_MINUTES` (default 12h) |
| Hand-offs | The bot tags `setter-needs-human`, sends a hand-off line, and stops. Build a GHL workflow on that tag to notify you. Remove the tag and `POST /leads/{id}/resume` to hand back |
| Other tags | `setter-link-sent` when the booking link goes out, `setter-disqualified` |

It never quotes a price: it deflects with "mind if I ask a few questions to build a quote out?" and keeps
qualifying. The bot always hands off for coaching, nutrition or medical advice, injuries, mental health or
distress, complaints, refunds, under-18s, and "am I talking to a bot?". It never claims to be the coach.

## Layout
```
setter/brain.py      Claude call, operating rules, output schema, booking-link handling
setter/engine.py     one reply cycle: guards → decide → send → tag
setter/server.py     FastAPI webhook, debounce, pause/resume/reload endpoints
setter/ghl.py        GoHighLevel API client
setter/store.py      SQLite: per-lead stage/notes, bot message IDs, decision log
setter/simulate.py   terminal chat
scripts/train.py     learn from your DM exports
evals/               simulated-lead test suite
```
